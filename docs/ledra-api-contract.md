# Ledra 外部API の仕様（カーケイボー連携）

別紙02「Ledra 側開発依頼書：カーケイボー連携API」で Ledra に追加する API の形です。
**2026-10-23 確定：Ledra 側がこの形に合わせて実装する。** Ledra 側の実装は holy-auto/Ledra #1397（設計書 `docs/consumer-app-oil-records-design.md`）。

カーケイボー側の呼び出しは次の2ファイルにまとまっています。

- `supabase/functions/_shared/ledra-client.ts`（呼び出し）
- `supabase/functions/_shared/ledra-records.ts`（応答の変換・QR の読み取り・同意の文言）

## 認証

- 接続先 `LEDRA_API_BASE_URL` は `https://<Ledra のホスト>/api`（下のパスはこの後ろに付く）
- `Authorization: Bearer <LEDRA_API_KEY>`
- キーはカーケイボー専用に、Ledra の外部API管理画面（`/admin/platform/passport-consumers`）で発行したもの。
  スコープは `passport:oil_records`（2026-10-23 確定。Ledra の既存の命名 `passport:verify` 等に合わせた）。
  **このスコープを明示した鍵が要る**（全スコープ `*` の鍵では `403`）
- 成功の応答には `ok: true` が付く（読まなくてよい）。エラーは `{ error, message }`
- `401`（鍵が無効）・`403`（スコープ不足）・`429`（レート制限・月間上限）は**設定や回数の問題**で、連携の状態とは関係ない
- キーはカーケイボーのサーバー（Supabase Edge Functions の secrets）だけに置き、アプリには埋め込まない

## QR コード

- 中身は「使い捨てトークンだけ」または「`?token=` 付きの URL」のどちらでも読める（`extractLinkToken`）
- Ledra のトークンは `lct_` + 43 文字（英数字と `_` `-`）。読み取りは英数字と `._~-` の 16〜512 文字を受け付ける
- 車体番号・個人情報は含まない（02 の 3.1）。有効期限 15 分

## 0. トークンの事前照会（同意画面の表示前）

2026-10-23 確定：01 の 5.5「同意画面に提供元（整備工場）を明記する」ため、02 に追加する。

```
GET /v1/consumer-link-tokens/{token}
```

| 応答 | カーケイボー側の扱い |
| --- | --- |
| `200` `{ "shop_name": "たにぐち自動車 本店", "expires_at": "2026-10-23T01:38:45.000Z" }` | 同意画面の「提供元」に店舗名を表示する |
| `410`（`400` / `404` も同じ扱い） | 「QR の有効期限が切れたか、すでに使われています」と表示し、同意画面を出さない |

- **トークンを消費しない**（照会しても有効期限まで使える）。車体番号・お客様の情報は返さない
- 同じスコープ（`passport:oil_records`）のキーで認証する
- 連携の確定（1.）の直前にも同じ照会を行い、表示した店舗名を `consent.provider_shop_name` として送る

## 1. 連携の確定

```
POST /v1/consumer-links
{
  "token": "<QR のトークン>",
  "consent": {
    "version": "2026-10-23.2",
    "recipient": "株式会社たにぐち自動車",
    "items": ["作業日", "走行距離（ODO）", "オイル交換の有無", "オイルフィルター交換の有無", "店舗名"],
    "agreed_at": "2026-10-23T01:23:45.000Z",
    "consumer_link_ref": "<カーケイボー側の連携ID（利用者のアカウントIDではない）>",
    "provider_shop_name": "<同意画面に提供元として表示した店舗名>"
  }
}
```

| 応答 | カーケイボー側の扱い |
| --- | --- |
| `201` `{ "link_id": "...", "shop_name": "..." }` | 連携成立。`shop_name` は任意（なければ事前照会の店舗名を使う） |
| `410`（`400` / `404` も同じ扱い） | 「QR の有効期限が切れたか、すでに使われています」と表示 |
| `409` | この車両は Ledra 側ですでに連携中（別のアカウントの連携が残っているなど）。前の連携を解除してもらう |
| それ以外 | エラー表示 |

- QR のトークンは1回限り。`409` のときはトークンを消費しない

`consent` は、Ledra 側で同意の記録（いつ・誰が・どの車両に・どの範囲で・提供先）を残すための材料です。「誰が」は利用者を特定しない `consumer_link_ref` で渡しています（必要なら Ledra 側で別の値を指定してください）。

## 2. オイル交換記録の取得（差分）

```
GET /v1/consumer-links/{link_id}/oil-records?since=<cursor>
```

```json
{
  "records": [
    {
      "record_id": "rec_123",
      "work_date": "2026-10-01",
      "odo_km": 41000,
      "oil_changed": true,
      "filter_changed": false,
      "shop_name": "たにぐち自動車 本店",
      "voided": false
    }
  ],
  "next_cursor": "opaque-cursor",
  "has_more": false
}
```

- 初回は `since` なし。以後は前回の `next_cursor` を渡す（中身は不透明。`has_more: true` のときは続けて取得する）
- 同じ `record_id` が再度来たら、訂正として上書きする（Ledra は取りこぼし防止のため、前回の位置より少し前から返すことがある）
- `voided: true` の記録は、整備工場が証明書を取り消した・非表示にしたもの。こちらの記録を消す（2026-10-23 確定）。
  後から非表示を戻すと、同じ `record_id` が `voided: false` でまた届く（そのときは取り込み直す）
- `odo_km` が `null` の記録は取り込まない（次回の目安を計算できないため）
- 上の項目以外が含まれていても取り込まない（氏名・住所・電話番号・他の整備・写真・金額は受け取らない）
- 返るのは、QR を出した店舗のその車両の記録だけ（2026-10-23 確定）
- `404` / `410` は「連携が無効（解除・所有者移転・顧客の付け替えなど）」とみなし、以後は取得しない。`503` は一時的な失敗なので次の回に取り直す
- 呼び出しは 1時間ごと＋連携確定の直後に1回（有効な連携1件につき）

## 3. 連携の解除

```
DELETE /v1/consumer-links/{link_id}
```

- `204` を返す（解除済みの連携も `204`）。`404` / `410` も解除済みとみなす
- 失敗した場合、カーケイボー側は取得を先に止め、解除の通知を1時間ごとに再送する

## 4. タイヤ・ブレーキの記録の取得（差分）

**2026-10-31 確定・実装。** 整備工場が Ledra の**点検表**で測って記録し、カーケイボーへ証明付きで届ける。
利用者が自分で溝などを確かめたときの記録は、カーケイボーの中で残せる（`wear_checks`、`source = 'manual'`）。

```
GET /v1/consumer-links/{link_id}/wear-records?since=<cursor>
```

```json
{
  "records": [
    {
      "record_id": "rec_456",
      "kind": "tire",
      "work_date": "2026-11-10",
      "odo_km": null,
      "replaced": false,
      "remaining_mm": 4.2,
      "shop_name": "たにぐち自動車 本店",
      "voided": false
    }
  ],
  "next_cursor": "opaque-cursor",
  "has_more": false
}
```

- 鍵のスコープは `passport:wear_records`（オイル交換の `passport:oil_records` とは別に付与する）
- 元になるのは Ledra の点検記録。点検表の「タイヤ溝の深さ」「ブレーキパッドの厚さ」の測定項目（項目に決まった印
  `tire_tread_min_mm` / `brake_pad_min_mm` が付いたもの）に値が入っているものだけが届く。1回の点検でタイヤとブレーキの
  両方を測ったら2件（同じ `record_id` で `kind` 違い）。こちらは `(vehicle_id, kind, ledra_record_id)` で上書きする
- `remaining_mm` は、いちばん減っているところの残り（タイヤは溝の深さ、ブレーキはパッドの厚さ）
- 点検の記録なので `replaced` は `false`、`odo_km` は `null`（点検記録は走行距離を持たない）
- **同意の範囲**：同意の控え（`consent.items`）に「タイヤの溝の深さ」「ブレーキパッドの厚さ」「タイヤ・ブレーキパッドの交換の有無」の
  3つがそろっている連携にだけ渡す。同意の版は `2026-10-31.1`。それより前（オイル交換だけ）に同意した連携は `403` を返す。
  `403` は連携の無効ではないので、こちらは連携を止めず、タイヤ・ブレーキの取り込みだけを飛ばす
- 差分の位置は、オイル交換とは別に持つ（`ledra_links.wear_sync_cursor`）
- `voided: true` は、点検表の測定項目を店舗が空欄に直したもの（その種類の記録を消す）。`remaining_mm` は `null`
- `404` / `410` / `503` の扱いは 2章と同じ

決まっていないこと：
1. **点検記録の削除・車両の付け替え。** 値を空欄にした場合は `voided` で伝わるが、点検記録そのものを消したとき・別の車両に
   付け替えたときは伝わらない（Ledra の点検記録に取消の状態が無い）
2. **既存の連携の同意の取り直し。** オイル交換だけに同意した連携は、タイヤ・ブレーキを受け取れない。取り直しの導線は無い
   （正式リリース前で、既存の連携はほぼ無い見込み【要確認】）
3. 交換の記録（施工証明書の「タイヤ交換」「ブレーキ整備」）は、まだ渡していない（`replaced: true` の記録は今は来ない）
4. 測定機器の記録（デプスゲージで測ったか、目で見たか）を渡すか
