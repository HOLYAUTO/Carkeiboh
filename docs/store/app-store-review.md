# App Store の審査に出す手順と、入れる内容

ビルドの申請（`eas submit`）は App Store Connect に上げるところまで。**審査に出すのは App Store Connect の画面で行う**
（API で出すには App Store Connect の API キーが要り、このリポジトリには無い）。

## 1. 審査に出す前に埋めること（残り）

| # | やること | 誰が | 状態 |
| --- | --- | --- | --- |
| 1 | プライバシーポリシー・利用規約の【要確認】（住所の番地・代表者・連絡先・制定日など）を埋め、たにぐち自動車の確認を受ける（`社内資料/法務/`） | たにぐち自動車・HOLY | 【要確認】は埋めて公開済み（2026-11-19、制定日 2026年12月1日。公開版の文面は holy-auto/holy-inc の `src/content/ijilog/`）。たにぐち自動車と専門家の確認は未 |
| 2 | 2つを **HOLY のホームページ**に公開し（2026-11-14 決定）、URL をアプリ（`eas.json` の production の `EXPO_PUBLIC_PRIVACY_URL`・`EXPO_PUBLIC_TERMS_URL` と EAS の production の環境変数）とストアに入れる | HOLY | 2つとも公開・`eas.json` に設定済み（https://www.holy-inc.jp/ijilog/privacy、https://www.holy-inc.jp/ijilog/terms）。ストアへの入力は未 |
| 3 | 定期購入 `ijilog_plus_monthly`（サブスクリプショングループ「複数台プラン」）と消耗型 `ijilog_restore_fee` を作る。最初のバージョンには定期購入だけを付ける（手順は `docs/store/app-store-iap.md`） | HOLY | 未 |
| 4 | スクリーンショット（6.9インチ：1320×2868 など）を、TestFlight で入れた実機から撮る | HOLY | 未 |
| 5 | カテゴリを決める | HOLY | 決定（2026-11-21）：ライフスタイル／ファイナンス（`docs/store/store-listing.md` 5章）。App Store Connect への入力は未 |
| 6 | 下の「App のプライバシー」「年齢制限」を入れる | HOLY | 未 |

審査用のアカウントは**要らない**：Apple でサインイン、または審査する人のメールアドレスに届くコードでログインでき、初めてのログインでアカウントができる。
審査へのメモは `docs/store/store-listing.md` の4章をそのまま貼る。

## 2. 画面での出し方

1. アプリ → イジログ → 「配信」タブ → 左の列の「iOSアプリ」のバージョン（1.0）
2. 「ビルド」で 11 を選ぶ（2026-11-21 に作ったストア版。輸出コンプライアンスは `ITSAppUsesNonExemptEncryption: false` を入れてあるので聞かれない）
3. 「プロダクトページ情報」の概要・キーワード・サポート URL・スクリーンショットを入れる（文面は `docs/store/store-listing.md`）
4. 「App 内課金とサブスクリプション」に 2 つの商品を付ける（1 の #3）
5. 「App Review に関する情報」に連絡先と、メモ（`store-listing.md` の4章）を入れる。「サインインが必要」はオフにする（オンにすると ID・パスワードが必須になる。審査する人は自分でアカウントを作れる）。ログインのしかたはメモに書いてある
6. 「審査用に追加」→「審査へ提出」

## 3. App のプライバシー（App Store Connect → App のプライバシー）

**トラッキング：しない**（外部の広告・計測サービスを使わない。ほかの会社のデータと結びつけない）。
「収集」は、端末の外に送り、その場の処理より長く残すものだけ（写真の読み取りで Claude API に送る写真は保存しないので入れない）。

| データの種類（Apple の区分） | 何が当たるか | 目的 | ユーザーに紐づく |
| --- | --- | --- | --- |
| 連絡先情報 → メールアドレス | ログインのメールアドレス | アプリの機能 | はい |
| 連絡先情報 → 名前 | 車検証の所有者・使用者の氏名 | アプリの機能 | はい |
| 連絡先情報 → 物理的な住所 | 車検証の住所・使用の本拠の位置 | アプリの機能 | はい |
| ユーザコンテンツ → 写真またはビデオ | 愛車の写真 | アプリの機能 | はい |
| ユーザコンテンツ → その他のユーザコンテンツ | 給油・整備・維持費・期限の記録 | アプリの機能 | はい |
| 購入 → 購入履歴 | 複数台プランの購入の記録 | アプリの機能 | はい |
| 位置情報 → おおよその場所 | ガソリンスタンドを調べるときの約5km四方の区画 | アプリの機能 | いいえ |
| ID → ユーザ ID | アカウントの ID | アプリの機能 | はい |
| 使用状況データ → 製品の操作 | 整備工場の画面の操作の記録、入力にかかった時間・入力方法 | 分析、アプリの機能 | はい |
| 使用状況データ → 広告データ | スポンサー広告を表示した・押した記録 | デベロッパの広告またはマーケティング、分析 | はい |
| その他のデータ | 車検証の記載内容（ナンバー・車台番号・型式など） | アプリの機能 | はい |

正確な位置情報は収集しない（端末の中だけで使う）。プライバシーポリシーを変えたら、この表もあわせて直す。

## 4. 年齢制限（年齢制限の質問）

暴力・性的な内容・ギャンブル・薬物・ホラーなどはすべて「なし」。
ユーザーどうしのやりとり（チャット・投稿）：なし。制限のない Web アクセス：なし（規約などを開くだけ）。
広告：あり（スポンサー広告。整備工場・カー用品などで、年齢に関わる内容は載せない）。
→ 4+（または 4+ 相当）になる見込み。

## 5. 差し戻しの記録

### 2026-11-23：利用規約（EULA）のリンクが無い（ガイドライン 3.1.2）

自動のメッセージで「複数台プラン(月額) は自動更新のサブスクリプションなのに、ストアのページに利用規約（EULA）の使えるリンクが無い」として審査が止まった。
ビルドの問題ではないので、**新しいビルドは要らない**。App Store Connect の入力だけを直す。
2026-11-24、下の手順で直して審査に出し直した。

1. 「配信」タブ → 左の列の「iOSアプリ」の 1.0 →「プロダクトページ情報」の「概要」の最後に、次の2行が入っていることを確かめる（無ければ足して、右上の「保存」）
   ```
   利用規約（EULA）：https://www.holy-inc.jp/ijilog/terms
   プライバシーポリシー：https://www.holy-inc.jp/ijilog/privacy
   ```
   右上の言語（「日本語 ∨」）に日本語のほかの言語があれば、そのすべての「概要」に入れる
2. 「App 情報」→「プライバシーポリシー URL」に https://www.holy-inc.jp/ijilog/privacy が入っていることを確かめる
3. 2つの URL をブラウザで開き、ログインなしで表示されることを確かめる
4. 左の列の「App Review」で Apple のメッセージに返信し、バージョンの画面の右上「審査内容を更新」で審査に出し直す

返信の文面：
```
Thank you for your review.
We have added a functional link to our Terms of Use (EULA) to the App Description:
Terms of Use (EULA): https://www.holy-inc.jp/ijilog/terms
Privacy Policy: https://www.holy-inc.jp/ijilog/privacy
The same links are also available in the app, at the bottom of the subscription screen
(Settings > クルマの切り替え・追加 > 複数台プランを見る) and in Settings.
We have resubmitted the app for review.
```
